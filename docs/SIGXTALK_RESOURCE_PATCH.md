# Resource/RNG compatibility audit

Upstream algorithm: SigXTalkR0.1.0, official repository `LithiumHou/SigXTalk`, verified commit `4d8055c6c9539ff9e6875d0e731d933cb2dd69f9`. Authors: Jiawen Hou, Wei Zhao and Qing Nie. Upstream is MIT licensed. Our public workflow imports the package and supplies its inputs; it does not vendor the upstream repository or claim authorship of its HGNN/PRS algorithms.

The configured runtime wrapper changes only:

1. The official `PRS_calc` SOCK worker cap, from24 to the configured4 by default.
2. An explicit worker RNG stream and a seed `20261017 + task_index` for each deterministically ordered TF–target task.
3. The ranger per-worker thread option, set to1.

It leaves the official TF×target normalized-expression response, receptor predictor set/scaling, 500-tree ranger regression, mtry3, permutation importance, coexpression rule, and >1e-5 positive-importance export unchanged. The stochastic realization is now specified; reduced workers and explicit task seeds are **not** a promise of numerical identity to the historical run or to an unseeded upstream invocation. No PA/PRS threshold or biological candidate is tuned by this patch.

`patches/PRS_workers_rng_default.patch` is a small, attributed source-level illustration for the default cap/seed. The runtime does not edit the shared installed package or its checkout: it deparses the imported official function, verifies the exact two patch locations, creates a bounded function in the same namespace environment, and records the upstream/runtime function copies plus the actual unified diff in the private run audit directory. The driver generates `PRS_resource_rng.patch` from those runtime copies. The runtime copies are audit artifacts and must not be published as our own source.

Fidelity and specificity are obtained from unchanged official `Calculate_Fidelity_Matrix(...)$all` and `Calculate_Specificity_Matrix(...)$all`. They are exported separately for the all-positive-PRS and relative-max-filtered universes, with explicit denominator sums. These are allocation ratios within the supplied universe, not p-values or causal confidence. The older `Calculate_Pathway_Fidelity` has a variable-name problem and is not substituted with a homemade `_like` measure. The packaged `PlotXT_FidSpe` helper uses additional SSC-conditional choices; our Python figure labels the exact two matrix-all definitions instead of silently mixing denominators.

Other transparent execution settings: Seurat v3 assay containers are requested through the supported creation option to satisfy the actual official assay accessors. Main HGNN uses an unchanged copy of official `vignettes/main.py`; a private filesystem outputs-directory link selects the new output location without changing its program. `PYTHONHASHSEED=20261017` fixes hash/set iteration alongside the declared official random seed; OMP/BLAS thread caps affect resource allocation. No old pathways, weights, PRS rows or gene-specific rescue is used.

An initial real PBMC technical attempt exposed a compatibility error in our own getter: SeuratObject5.4 rejects the deprecated GetAssayData `slot=` argument. Our helper was corrected to the supported `layer=` argument before retrying the same frozen configuration. The official source uses its own assay accessors and was not changed. Preserve the failed attempt log; do not present that failed invocation as a completed smoke or an upstream algorithm failure.

The following real attempt exposed a separate installed-package mismatch: Seurat5.2.1 internally called defunct SetAssayData `slot=` under SeuratObject5.4. That is not addressed by altering official SigXTalk mathematics or replacing arbitrary namespaces. The isolated R environment must use a supported compatible SeuratObject version, preferentially5.0.2 with Seurat5.2.1 under R4.4; if the package solver cannot provide that build, a separately verified compatible5.2.0 environment is a documented alternative. Record actual resolved versions and a fresh-session successful real-data loop before certifying the environment. The bootstrap file is a setup recipe, not evidence that any package installation or smoke has succeeded.

The main input setting (`datatype=data`, expression/CCC thresholds.1, Fisher1, top200 receiver variance targets) follows the predeclared comparable IVDD design and differs from the markdown tutorial's scale.data/.05 illustration. It is a declared application parameter, not a hidden source modification. PBMC technical smoke alone uses <=30 real cells per original identity, at most50 marker-derived targets and at most25 predeclared sorted TF–target PRS tasks. The initial two-epoch run completed R preparation and HGNN but had zero PA>.75 paths and no completed PRS. A separate technical_smoke_100epochs directory preserves that attempt while applying the official standard100-epoch training length with the same PBMC targets and thresholds. No activation/PRS rescue threshold or named gene was introduced. This remains a technical subset, not the full published PBMC experiment. The IVDD formal run has100epochs, all selected target/prior axes and all active PRS tasks.
