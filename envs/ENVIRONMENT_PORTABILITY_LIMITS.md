# Environment portability review

The current files correctly distinguish a setup recipe, installed-version evidence and a platform-specific lock. They should retain those labels rather than describing every export as a portable environment recreation command.

1. `sigxtalk_r.bootstrap.yml` is a useful Linux bootstrap, but is not the final source-overlay lock. The successful environment used R4.4.3 and the compatible Seurat5.2.1/SeuratObject5.0.2 pair. Conda package builds can constrain that exact pair; if solving fails, use the recorded compatible source installation rather than allowing an unbounded SeuratObject upgrade. The actual source-installed NMF/tidyfst/CellChat/presto/SigXTalkR versions and commits must accompany the conda explicit file. An explicit conda URL list recreates conda-managed packages on its recorded platform only; it does not capture packages subsequently installed into R from source.
2. The recorded installed R table and source-provenance JSON are valuable, portable metadata. They are evidence, not a complete restore script. Keep actual package versions/builds and source commits. Remove personal installation prefixes/private source directories from public exports. Do not rewrite these records to match the bootstrap's earlier versions.
3. A scientific Python3.12 `pip list` requirements export from the broad gsMap environment can include unrelated packages. Keep it as the actual-run snapshot, and supply the smaller module requirements separately. Python3.8 HGNN and scientific Python3.12 must remain separate. Package names/versions alone may not encode the PyTorch CPU/CUDA wheel index, compiled graph-library compatibility, conda BLAS stack, or a package installed directly from the pinned official checkout.
4. The human projection requirements are intentionally loose except decoupler2.2.0. This is a functional minimal specification, not an exact stochastic/version lock. For a scientific rerun, use actual successful versions and record where `python_addons` were installed; packages imported from a separate target directory can be absent from a base environment's `pip list`. NumPy and SciPy versions also matter for matching the one fixed spatial draw. The already-completed draw must be verified/reused rather than repeated after an environment update.
5. `historical_discovery_requirements.txt` records the old scientific Python dependencies, but the Python3.10.20 interpreter, separate historical UCell2.4.0/R4.3.1 closure and compiled R/Python system libraries remain part of reconstruction. The explicit cNMF command/seed is supplied; nominally matching package names is not proof of bit-identical spectra.
6. `lightweight_ci_requirements.txt` being unpinned is acceptable for source/structural compatibility checks, provided it is never called the scientific environment lock. CI neither fetches study raw data nor trains models. It does not certify the current R loop or from-raw numerical reproduction.

For this actual cached run, do not install, upgrade or solve any environment. Use the already-successful executable paths. Keep top-level `PYTHONPATH` unset so scientific target-directory packages cannot shadow Python3.8 HGNN dependencies. The private human config injects its own scientific addons only for that module. Finalization records the actual R session, separate Python environment and model/source/log hashes.
